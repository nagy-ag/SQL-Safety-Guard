# Release 1.1.0

[SQL Safety Guard 1.1.0](https://github.com/nagy-ag/SQL-Safety-Guard/releases/tag/v1.1.0) was published on
**2026-11-17 at 08:59:05 UTC** as an acceptance **prerelease**, at the owner's request. **1.0.5 remains stable and Latest**;
promoting this package awaits owner acceptance. All five GitHub assets are unsigned and target 64-bit
**SSMS 22.0 and later 22.x releases**, bounded to `[22.0,23.0)`.

## Changes since published 1.0.5

- Supported straight-line variable-backed dynamic SQL: declarations, assignments, copies and concatenation. Unproved
  runtime strings remain yellow. Decoded operations navigate to supporting string ranges and their EXEC anchor.
- Typed visible previews for procedures, triggers, scalar/inline/multi-statement functions, views, remote query strings
  and stored SQL Agent T-SQL commands. Unknown function calls receive yellow findings, including embedded expressions.
- Fully qualified target approvals and separate procedure/function approvals. Conservative database contexts retain
  prior possibilities after USE, scope dynamic context changes and honor stricter destination environment rules.
- Compact object/operation rows, persistent highlights, joined adjacent outlines, full-definition context outlines,
  lowest-level whole-target explanations, six independent adaptive filters and semantic hover descriptions.
- A shared measured line gutter, scope-only header and numbered collapsed summary, with spacing between risk and
  scope/context colors. Purple Inside and gray Remote totals remain separate from submitted risk counts; USE is blue.
- Readable dark settings, a structured six-color dictionary, migration guidance and inspection-only samples.

**Upgrade:** old short approval rules retain their text but are inactive until explicitly qualified as
server.database.schema.object. Missing identities are never guessed. Procedure and function rule types are separate.
AllowListed authorizes the matched operation/call and its reachable effects; it does not prove a read-only implementation.
See the [upgrade instructions](../../user/install.md#upgrading-to-110), [settings](../../user/settings.md),
[dictionary](../../user/dictionary.md) and [changelog](../../../CHANGELOG.md).

Dynamic SQL depth remains 3 and visible-preview depth remains 8. Resource limits and unavailable proof remain visible.
The production extension opens no SQL connection, executes no SQL and retrieves no deployed definitions or metadata.
F5 still analyzes the submitted selection/window and uses button-only confirmation. Display filters never change it.
